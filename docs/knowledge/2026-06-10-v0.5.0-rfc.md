# v0.5.0 RFC: Enterprise-Dev-Flow Skills

Date: 2026-06-10

## Goal

Decide what v0.5.0 should ship for the local skill collection, given the user's directive: "补 superpowers 中缺的企业级开发技能". Land the decision as a knowledge note so future readers understand why v0.5.0 is a "slim orchestrator + RFC" rather than a batch of new skills.

## Context

`obra/superpowers` is the adjacent skill collection the user references. It covers 14 generic-author-craft skills (TDD, debugging, brainstorming, writing-plans, requesting/receiving code review, finishing-a-development-branch, subagent-driven development, using-git-worktrees, using-superpowers, writing-skills). It deliberately does not cover org-context / enterprise concerns: multi-team coordination, compliance, change governance, reliability, security engineering, data governance, tech-debt and cost, AI governance.

The local collection at the time of this decision ships 8 skills: 5 language-specific production-risk code reviewers, `goal-driven-development` (spec → code), `project-knowledge-capture`, and `spec-doc-linter`. The collection's coverage gap is the same enterprise layer that superpowers refuses to assume. The user wants the gap closed without competing with superpowers.

The first proposal in the planning session was 7 CodeGraph-deep enterprise skills (data-lineage, code-ownership, incident-call, progressive-rollout, compliance-control, cross-team-RFC, observability-coverage). After the user clarified that the design centre should be the dev flow itself (not CodeGraph), the proposal was reframed as 6 flow skills. The user then clarified again that any new skill must not duplicate superpowers; the 6 flow skills were re-checked against the 14 superpowers skills and 3 of the 6 (`spec-intake`, `plan-decompose`, `test-scaffold`) were rejected as duplicates of `brainstorming`, `writing-plans`, and `test-driven-development` respectively.

## Decisions

- **v0.5.0 ships 0 new skills.** The 8 RFC'd skills land in v0.5.1+, in leverage order: `data-lineage-trace`, `code-ownership-impact`, `incident-call-trace`, `progressive-rollout-checklist`, `compliance-control-walk`, `observability-coverage-audit`, `cross-team-rfc-draft`, `pr-authoring`. Per-skill release with the same shape as `spec-doc-linter` (SKILL.md + README + co-required prompts + bad/good example pairs + canonical output sample).
- **Thin `goal-driven-development` to a router.** The 6 phases are kept; the body no longer carries install-path detail (already in README) and no longer duplicates the CodeGraph-fallback clause. Each phase names the skill that does the work and, where applicable, the future-skill that will replace the inline work.
- **Fix the stale `codegraph.md` prompt.** The current `@colbymchenry/codegraph` API no longer exposes `codegraph_context` or `codegraph_trace`; `codegraph_explore` is the primary walk tool. Without this fix, the v0.5.1+ skills would bind to a tool surface that no longer exists and silently fail.
- **CodeGraph is a tool, not a design premise.** The 8 RFC'd skills list `codegraph_explore` / `codegraph_impact` / `codegraph_callers` etc. as the primary tools, but every skill has a `rg` + file-read fallback. A consumer without CodeGraph installed is not blocked.
- **No duplication with superpowers.** Every RFC'd skill names the closest superpowers skill and the boundary. `pr-authoring` is the only skill that overlaps in *shape* with `requesting-code-review`; it differs in language (中文 vs English) and in scope (org template + CODEOWNERS + cross-repo link format).

## Review Conclusions

未发现明确高风险问题。

The decision to ship 0 new skills in v0.5.0 is intentionally conservative. The 8 RFC'd skills are well-scoped but each has its own enterprise context (regulator frame, flag system, on-call tool, etc.) and a per-skill release gives each one its own rollback surface if it turns out to be wrong.

## Follow-up Notes

- The 8 RFC'd skills' v0.5.1+ schedule is by leverage, not by simplicity. The simplest skill (`observability-coverage-audit`) lands *after* the regulator-heavy ones because the audit reveals what a regulated consumer actually needs in the gap report.
- `pr-authoring` is the only skill in the 8 that overlaps in shape with a superpowers skill (`requesting-code-review`). The overlap is intentional: superpowers' skill is the English / generic version; `pr-authoring` is the 中文 + 企业 CI + 多 reviewer variant. Future contributors should not "merge" the two — they coexist for different consumer sets.
- The thin orchestrator commit is the right home for the `codegraph.md` fix because the two changes together redocument the goal-driven-development contract. A future contributor reading the git log will see them together.
- If the user wants to land any of the 8 RFC'd skills sooner, the priority order in the RFC is the order to follow. Do not land them as a single mega-release.
