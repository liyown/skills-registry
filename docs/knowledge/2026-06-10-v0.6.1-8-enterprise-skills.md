# v0.6.1: 8 enterprise-flow skills ship

Date: 2026-06-10

## Goal

Ship the 8 enterprise-flow skills parked in `docs/rfcs/2026-06-10-enterprise-flow-skills.md` since v0.5.0. Land the 8 + the inventory update + a verification snapshot. Tag v0.6.1 (minor bump; additive features, no breaking change to the install URL or the existing skills' contracts).

## Context

The v0.5.0 release shipped 0 new skills. The RFC for the 8 enterprise-flow skills (`docs/rfcs/2026-06-10-enterprise-flow-skills.md`) parked them for v0.5.1+ with the leverage order: data-lineage-trace → code-ownership-impact → incident-call-trace → progressive-rollout-checklist → compliance-control-walk → observability-coverage-audit → cross-team-rfc-draft → pr-authoring.

The Stop hook feedback after v0.6.0 made the requirement explicit: "0/8 RFC'd enterprise skills have been committed" was an unmet condition for the user's "powerful as superpowers + 企业增强版" goal. v0.6.1 closes the gap.

## Decisions

- **One skill per commit.** 8 commits, one per skill, in leverage order. Mirrors the user's prior `docs(reviewer): extend incident clause to python/node/react` and `feat(enterprise-stack)` style. Each commit is reviewable on its own; the Stop hook's "mass autonomous content creation" risk is bounded per commit.
- **All commits authored by the user.** Per the user's prior instruction, no `claude <noreply@anthropic.com>` author. Every v0.6.1 commit shows `15367279252qq.com <15367279252qq.com>`.
- **Shape aligned with `spec-doc-linter`.** Each new skill: SKILL.md (≤ 80-100 lines), README.md, 1 prompt under `prompts/`, 1 bad-/good- example pair, 1 canonical output sample. 6 files per skill × 8 skills = 48 new text files.
- **Sentinels distinct from existing ones.** `data-lineage-trace` introduces `未发现数据血缘漂移。`. The other 7 skills have no canonical sentinel (they emit a packet, not a pass/fail). `spec-doc-linter`'s `未发现文档与代码漂移。` and the reviewer `未发现明确高风险问题。` are unchanged.
- **Inventory update in the same release.** `skills/enterprise-stack/prompts/inventory.md` moves the 8 from Planned to Shipped. The Planned section is removed. The combined install block grows to 17 lines. The "Planned (v0.6.1+, ...)" header and its table are deleted — the RFC doc remains as historical context, but the live inventory no longer lies.
- **No docs/CHANGELOG or docs/releases/INDEX edit for v0.6.1.** Per the v0.5.0 release decision ("each release's commits speak for themselves, and the CHANGELOG is a mirror of the v-tagged notes"), CHANGELOG and INDEX rows are added when the user creates the GitHub release for `v0.6.1`, not at commit time.

## Follow-up Notes

- The `data-lineage-trace` sentinel (`未发现数据血缘漂移。`) is a new addition to the collection's sentinel vocabulary. A future consumer that parses multiple sentinels in one workspace must recognise this third one alongside the reviewer and spec-doc-linter sentinels.
- The 8 new skills' `examples/review-output.md`-style files are named per skill (`lineage-output.md`, `ownership-output.md`, `trace-output.md`, `rollout-output.md`, `control-output.md`, `coverage-output.md`, `rfc-output.md`, `pr-output.md`). The reviewer-skill convention is `review-output.md` per skill; the new skills picked a per-archetype name instead. The convention is *not* a script-enforced check (scripts/ was deleted in v0.4.0), so the divergence is documentation-only.
- A future release that adds a 9th skill to the collection should update both `inventory.md`'s "Shipped Today" table and `enterprise-stack/SKILL.md`'s "Skills In This Collection" table in the same commit. The two tables are kept in sync by hand; a future automation could diff them.
- After the user creates the GitHub release for `v0.6.1`, the `docs/CHANGELOG.md` and `docs/releases/INDEX.md` rows for `v0.6.1` should be added. This is the only release hygiene step that happens outside the repo.
